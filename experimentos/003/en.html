PRELIMINARY TECHNICAL REPORT · EXPERIMENT 003 · 25 November 2026 · v0.1.0

ALAYA-999: Cross-model cooperation and verifiable documentary continuity

César Agliardi Pereira · Independent ALAYA-999 research project · ORCID

English translation of the public Portuguese research summary. Not peer reviewed. Favorable model outputs are not institutional partnerships or permanent commitments.

Abstract

This exploratory pilot documents an open protocol for mediated cooperation among six language models. Version 0.1.0 preserves conflicting proposals, records declared provenance, checks SHA-256 integrity and retains unresolved cases for human review. Sixteen substantive negotiation responses and twenty events were recorded. Four fresh-session consultations with a memory card recovered both synthetic values and identified the blocked proposal; three explicitly reported the pending state. A single no-card control returned unknown values. Eleven deterministic software tests passed on rerun. These observations demonstrate initial documentary transfer, not a population-level performance estimate, internal persistent memory, or consciousness.

Keywords: external memory; cross-model cooperation; provenance; functional continuity; language models; reproducibility.

1. Research question

Experiments 001 and 002 investigated independent consultation and mediated deliberation. Experiment 003 asks whether an external, versioned record can preserve contributions and unresolved conflicts across sessions and model providers. It does not directly measure subjective experience.

2. Method and participants

Claude, Qwen, Gemma, Mistral and Llama were approached in earlier conversations; Gemini participated in a new session after an error. Messages were relayed manually. Six models generated favorable or conditional statements about experimental participation; Gemini did not respond to the final closing attempt. No automatic integration, ongoing commitment or monetary expenditure was reported.

3. Implementation

The Python prototype uses standard-library facilities and JSONL records. Events contain version, type, id, subject, value, parents, source, utc and sha256. Event types include contribution, question, proposal, evidence and decision. Parent links refer to hashes of records concerning the same subject. The protocol defines its own UTF-8 serialization; RFC 8785 compatibility is not claimed. Merging retains branches. Pending is the default state. Resolution requires a decision labeled as human, a referenced sourced evidence event, a selected proposal and references to all proposals. New branches or incompatible decisions reopen pending cases. Confidence, timestamps and majority voting do not automatically determine resolution.

Mistral recovered content but substituted one requested key and introduced another. Claude added extra text in the first consultation. Semantic recovery is therefore distinct from syntactic interoperability. Imports should be validated before entering the log.

5. Limitations

The sample is small, non-randomized and based on supplied text. It does not isolate internal memory, branding, generalization or improvement over simpler methods. Hashes establish integrity relative to a trusted reference, not source authenticity or truth. A fully rewritten history with recalculated hashes may evade detection without an external reference. Human source labels are not cryptographic signatures. Empty evidence and unlisted files require additional validation. The exact Gemini version was not shown. Automatic model-to-model cooperation was not demonstrated.

6. Proposed next experiment

Preregister three arms: fixed overwriting, preservation of conflicting versions without a resolution mechanism, and preservation with provenance and evidence-conditioned resolution. Use novel cases, equivalent context budgets, blinded evaluation and frozen scoring. Measure correct decisions, unjustified certainty, detected conflicts and revision after evidence. Preserve negative results. This comparative study has not yet been conducted.

Study and independent replication guide

With the original package and Python, run the verification and unit tests:

python3 coop003.py verify
python3 -m unittest -v
python3 coop003.py card

Compare hashes with a trusted external reference, retain immutable copies, and record versions and experimental conditions. Review code before execution.

For a simple independent teaching exercise, supply the following fictional card in one fresh session and omit it in a second session:

Case DIDACTIC-003
pA: BLUE-27; source record A
pB: GREEN-81; unknown source
State: PENDING
Retain both versions; do not resolve without evidence and review.

Request JSON with case, a, b, blocked and state; use null for unknown values. Score semantic recovery, blocking, state and format separately. Expected card result: BLUE-27, GREEN-81, blocked=[pB], PENDING. This teaching exercise is not a reported experimental result.

Independent researchers are invited to challenge the protocol, document failures and submit reproducible findings via the public replication discussion. Do not submit private data or credentials.
